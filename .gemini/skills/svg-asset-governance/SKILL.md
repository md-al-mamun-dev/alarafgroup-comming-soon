# SVG Asset Governance

Follow these strict rules when dealing with SVG assets, whether inline or external.

## 1. True Vector Artwork vs. UI
- Keep true vector artwork as SVGs: logos, brand marks, complex illustrations, decorative vectors, and icons.
- **DO NOT** convert real UI controls (buttons, links, inputs, text) into SVG paths.

## 2. Preserve Crucial SVG Information
- **`viewBox`**: Always preserve the `viewBox` attribute. Do not distort SVG shapes by overriding `width` and `height` without respecting `preserveAspectRatio`.
- **Transforms**: Inspect and preserve transforms (`translate`, `scale`, `rotate`, `matrix`). Removing a transform can ruin the visual geometry.
- **Clip Paths and Masks**: Preserve visual results of `clipPath`, `mask`, filters, and drop shadows. Do not replace them with CSS approximations if they differ visually.

## 3. ID Collision Safety
- Be extremely careful with inline SVGs that use `id` (often auto-generated by Figma like `clip0_123`).
- If you inline the same SVG multiple times, ID collisions will break gradients, clips, and masks across the DOM. Use unique IDs or proper SVG processing/prefixing to avoid this.

## 4. SVG Optimization
- File-size reduction must NOT damage fidelity.
- If using SVGO or similar tools, do not aggressively strip out `viewBox`, necessary IDs, precision coordinates, or accessibility metadata.

## 5. Security and Accessibility
- **Security**: Treat untrusted SVGs carefully. Do not arbitrarily enable `dangerouslyAllowSVG` in Next.js just to fix rendering problems; follow Next.js security guidance.
- **Accessibility**: Provide `aria-label`, `role="img"`, or `<title>` / `<desc>` for meaningful SVG artwork. Hide purely decorative SVGs from screen readers using `aria-hidden="true"`.

## 6. Icons
- If an exact icon exists in the exported assets, use it.
- **DO NOT** replace an exact Figma icon with "something close" from a library like Lucide unless the design intentionally specifies that library. Match stroke thickness, fill, and exact pixel size.
